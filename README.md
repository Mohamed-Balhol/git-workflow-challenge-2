لكن لا تفرح كثيرًا... لأن التحدي الحقيقي يبدأ الآن 😄

في هذا التحدي لن تكون مجرد طالب يطبق أوامر Git، بل ستلعب دور **Software Developer** يعمل داخل فريق برمجي حقيقي.

ستتعلم كيف يعمل المطورون في الشركات، وكيف يتعاملون مع المشاريع المشتركة، وكيف يحلون المشاكل البرمجية، وكيف يتجنبون فقدان أعمالهم عند العمل مع أعضاء الفريق.

⚠️ تذكر...
الأخطاء جزء طبيعي من البرمجة، وظهور Merge Conflict لا يعني أنك أخطأت، بل يعني أنك أصبحت تعمل بطريقة تشبه الواقع.

استمتع بالتحدي، وفكر كمطور محترف وليس كطالب يبحث عن إنهاء التكليف فقط.

# 🎯 الهدف من هذا التحدي

في هذا التحدي ستتعرف عمليًا على طريقة العمل داخل فرق البرمجة باستخدام **Git Workflow**.

ستتدرب على:

- إنشاء نسخة محلية من المشروع (Clone)
- تنفيذ تعديلات على مشروع حقيقي
- حل مشاكل برمجية
- كتابة Commit Messages احترافية
- رفع التعديلات إلى GitHub
- التعامل مع تحديثات الفريق
- حل Merge Conflicts
- التفكير بنفس الطريقة التي يعمل بها المطورون داخل الشركات

الهدف ليس حفظ أوامر Git...

الهدف هو **اكتساب طريقة التفكير الصحيحة أثناء العمل الجماعي.**

بعد الانتهاء من المشاكل البرمجية...

المطلوب منك تنفيذ **عدة تحسينات** على ملفات:

مثل:

- تحسين الألوان.
- تعديل الأزرار.

نريد أن نرى أسلوبك في التفكير وتحسين واجهة الموقع.

# 🌳 طريقة العمل (Git Workflow)

لا تعمل مباشرة على الفرع الرئيسي.

لكل تعديل تقوم به:

✅ أنشئ Feature Branch جديد.

نفذ التعديل.

اعمل Commit.

ثم Push.

ثم افتح Pull Request.

---

# ✍️ تسمية الـ Branch

استخدم أسماء واضحة تصف المهمة.

الصيغة المطلوبة:

```text
feature/page-name-yourName
```

أمثلة:

```text
feature/home-mohammed

feature/navbar-ahmed

feature/footer-ali

feature/button-khaled
```

---

# 📌 قبل إنشاء Pull Request

قبل أن تقوم برفع آخر تحديثاتك...

تأكد أولاً من سحب آخر التعديلات الموجودة في المستودع.

استخدم:

```bash
git pull origin main
```

أو قم أولاً بـ:

```bash
git fetch
```

ثم قم بدمج التحديثات.

---

# ⚠️ لماذا؟

لأن جميع الطلاب يعملون على نفس المشروع.

قد يقوم أحد زملائك بتعديل نفس الملف الذي تعمل عليه.

إذا لم تقم بسحب آخر التحديثات فقد تواجه:

✅ Merge Conflict

وهذا أمر طبيعي جدًا أثناء العمل الجماعي.

المطلوب منك في هذه الحالة هو حل التعارض ثم متابعة العمل.

---

# 📌 ملاحظات مهمة

✅ لا تحذف أي ملفات من المشروع.

✅ لا تعدل أسماء الملفات.

✅ لا تحذف أسماء الطلاب.

✅ لا تنس رفع جميع الفروع التي قمت بإنشائها.

✅ اكتب Commit Messages واضحة ومعبرة.

❌ لا تستخدم رسائل مثل:

```text
update

edit

fix

123
```

بل استخدم رسائل احترافية مثل:

```text
Update hero section

Improve button styles

Add new statistics card

Fix navigation links
```
